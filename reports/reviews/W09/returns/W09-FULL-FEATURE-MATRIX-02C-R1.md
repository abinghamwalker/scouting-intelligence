## Bounded-memory action strategy

The producer never materialises the 3,071,395-action population as Python dictionaries.

- Artifact SHA-256 is computed in 1 MiB file chunks.
- Action schema/build/temporal authority is checked in 65,536-row Arrow batches.
- Feature construction streams selected action columns in configurable Arrow batches.
- A batch's Python row dictionaries are ephemeral and discarded before the next batch.
- Retained state is compact per appearance-established grain only: 16 integer numerators,
  source-action count, valid-coordinate count, action-match-ID set, and one incremental
  SHA-256 state.
- The lineage hash frames canonical JSON for exact ordered action keys
  (`source_partition`, `source_member_path`, `source_record_ordinal`, `source_action_id`,
  `action_id`).
- Players, teams, matches, and 68,864 appearances remain in memory; the multi-million-row
  action population does not.

Fixture outputs, including the Parquet matrix bytes, are byte-identical at action batch
sizes 1 and 10,000. Their typed-row semantic digests are also identical. Reversing action
order while preserving feature semantics changes the source-lineage digest, proving the
ordered action-key binding.
